SparkMeter / EarthSpark stack (as heard)

SM meters (2.4 GHz, encrypted / hidden SSID) ↔ USB Gateway (runs on laptop) ↔ GroundBolt (site) ·via Gateway· ↔ ThunderCloud (= GroundBolt in the cloud)
  • Meters — SparkMeter field meters on 2.4 GHz; SSID encrypted or hidden.
  • Gateway — USB device; works attached to a laptop. Physical bridge to the meter RF.
  • GroundBolt — on-site app; talks to meters via the Gateway (not a separate radio hop labeled Firefly).
  • ThunderCloud — same app family as GroundBolt, deployed in the cloud.
  • SparkNet-HTTP and Firefly — described as software plugins (not standalone RF radios). Aligns with public sparknet-http repo being software; Firefly naming on older wiki diagrams likely overstated as hardware mesh gateways.

Wiki correction · RF vs software

Verified public: meters advertise built-in RF mesh; sparknet-http is open software; ThunderCloud / GroundBolt are the same web app, different deploy target.

Meeting correction: the USB Gateway is the hardware RF interface (laptop/site). Firefly + SparkNet-HTTP = plugins into that stack. Older village diagrams that draw multiple “Firefly radios” with coverage discs should be treated as provisional until redrawn against this model.

Open Code · STS vending

  • Open Code path today: basic meter reading · toggle relays.
  • Tokens / prepaid: STS. Do not redo vending — use existing STS token path.

A2EI Open Metering Infrastructure · Nimbus peer

  • Open Metering Infrastructure (A2EI) — CRM / operator platform layer. Use the full name only.
  • ThunderCloud (EarthSpark / SparkMeter) and Nimbus (SteamaCo) both sit under Open Metering Infrastructure — Nimbus ≈ SteamaCo’s ThunderCloud-class HES.
  • Nimbus uses a universal SGC (Security Group Code) key for token generation.

Priorities · OBIS vs Open Metering Infrastructure standards

Focus shift

OBIS / VMRS deep register work takes a back burner relative to standards and interfaces that drive progress on Open Metering Infrastructure (read · relay · STS tokens already in path · GroundBolt/Nimbus under A2EI). Keep VMRS as the short northbound checklist when needed; do not block Open Metering Infrastructure on a full OBIS campaign.
